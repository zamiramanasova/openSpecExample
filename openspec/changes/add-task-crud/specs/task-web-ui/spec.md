# Spec Delta

## Purpose

Определяет браузерную страницу, через которую пользователь просматривает и редактирует список задач, работая поверх HTTP API управления задачами.

## ADDED Requirements

### Requirement: Доступ к странице
Приложение SHALL отдавать HTML-страницу менеджера задач по запросу `GET /` на том же адресе, что и API.

#### Scenario: Открытие страницы
- **WHEN** пользователь открывает `http://localhost:8080/` в браузере
- **THEN** загружается страница менеджера задач

### Requirement: Отображение списка
Страница SHALL при загрузке показывать все задачи в порядке создания; у каждой задачи видны заголовок и признак выполнения. Выполненные задачи MUST визуально отличаться от невыполненных. При пустом списке страница SHALL показывать сообщение о том, что задач нет.

#### Scenario: Список с задачами
- **WHEN** в системе есть задачи и пользователь открывает страницу
- **THEN** страница показывает каждую задачу с её заголовком и состоянием выполнения

#### Scenario: Пустой список
- **WHEN** задач нет и пользователь открывает страницу
- **THEN** страница показывает сообщение, что задач нет

### Requirement: Добавление задачи
Страница SHALL содержать поле ввода и кнопку для добавления задачи; отправка возможна также клавишей Enter. После успешного добавления задача MUST появиться в списке без перезагрузки страницы, а поле ввода MUST очиститься.

#### Scenario: Добавление
- **WHEN** пользователь вводит «Купить молоко» и нажимает Enter
- **THEN** задача «Купить молоко» появляется в конце списка, поле ввода пустое

### Requirement: Отметка выполнения
Каждая задача SHALL иметь переключатель выполнения; его изменение MUST сохраняться через API и отражаться в списке без перезагрузки страницы.

#### Scenario: Отметить выполненной
- **WHEN** пользователь отмечает переключатель у невыполненной задачи
- **THEN** задача отображается как выполненная, и после перезагрузки страницы остаётся выполненной

### Requirement: Переименование задачи
Пользователь SHALL иметь возможность изменить заголовок существующей задачи со страницы; новое значение MUST сохраняться через API.

#### Scenario: Переименование
- **WHEN** пользователь меняет заголовок задачи на «Новое имя» и подтверждает
- **THEN** список показывает «Новое имя», и после перезагрузки страницы заголовок сохранён

### Requirement: Удаление задачи
Каждая задача SHALL иметь кнопку удаления; после успешного удаления задача MUST исчезнуть из списка без перезагрузки страницы.

#### Scenario: Удаление
- **WHEN** пользователь нажимает кнопку удаления у задачи
- **THEN** задача исчезает из списка

### Requirement: Показ ошибок
Если API отклоняет действие или недоступно, страница MUST показать пользователю понятное сообщение об ошибке и MUST NOT показывать изменение, которое не было сохранено.

#### Scenario: Пустой заголовок
- **WHEN** пользователь пытается добавить задачу с пустым заголовком
- **THEN** страница показывает сообщение об ошибке, и новая задача в списке не появляется
