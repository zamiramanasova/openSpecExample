# Spec Delta

## Purpose

Определяет жизненный цикл задачи (создание, просмотр, изменение, удаление) и HTTP API в формате JSON, через которое клиенты управляют списком задач.

## ADDED Requirements

### Requirement: Представление задачи
Каждая задача MUST содержать поля `id` (целое число, уникальное и неизменяемое), `title` (непустая строка), `done` (логическое значение) и `createdAt` (момент создания в формате ISO-8601). Все ответы API с задачами SHALL использовать это JSON-представление.

#### Scenario: Поля задачи в ответе
- **WHEN** клиент получает задачу через любой эндпоинт API
- **THEN** JSON-объект содержит поля `id`, `title`, `done` и `createdAt`

### Requirement: Создание задачи
Система SHALL создавать задачу по запросу `POST /api/tasks` с JSON-телом, содержащим `title`. Новая задача MUST получать новый `id`, `done = false` и текущее время в `createdAt`. Пробелы в начале и конце `title` SHALL обрезаться.

#### Scenario: Успешное создание
- **WHEN** клиент отправляет `POST /api/tasks` с телом `{"title": "Купить молоко"}`
- **THEN** система отвечает `201` и возвращает задачу с новым `id`, `title = "Купить молоко"` и `done = false`

#### Scenario: Обрезка пробелов
- **WHEN** клиент отправляет `POST /api/tasks` с телом `{"title": "  Позвонить  "}`
- **THEN** созданная задача имеет `title = "Позвонить"`

#### Scenario: Идентификаторы уникальны
- **WHEN** клиент создаёт две задачи подряд
- **THEN** у задач разные значения `id`

### Requirement: Валидация заголовка
Система MUST отклонять создание или изменение задачи, если `title` отсутствует, пуст, состоит только из пробелов или не содержит ни одной буквы или цифры (любого алфавита), ответом `400` с JSON-телом `{"error": "<сообщение>"}`. Отклонённый запрос MUST NOT менять список задач.

#### Scenario: Пустой заголовок при создании
- **WHEN** клиент отправляет `POST /api/tasks` с телом `{"title": "   "}`
- **THEN** система отвечает `400` с полем `error`, и задача не создаётся

#### Scenario: Отсутствует заголовок при создании
- **WHEN** клиент отправляет `POST /api/tasks` с телом `{}`
- **THEN** система отвечает `400` с полем `error`

#### Scenario: Пустой заголовок при изменении
- **WHEN** клиент отправляет `PUT /api/tasks/{id}` существующей задачи с телом `{"title": ""}`
- **THEN** система отвечает `400`, и задача остаётся без изменений

#### Scenario: Заголовок только из символов
- **WHEN** клиент отправляет `POST /api/tasks` с телом `{"title": "+"}` (или `"!!!"`, `"---"`, `"@#$"`)
- **THEN** система отвечает `400` с полем `error`, и задача не создаётся

#### Scenario: Символы рядом с буквами или цифрами
- **WHEN** клиент отправляет `POST /api/tasks` с телом `{"title": "C++"}`
- **THEN** система отвечает `201`, и задача создаётся с `title = "C++"`

### Requirement: Некорректное тело запроса
Система MUST отвечать `400` с JSON-телом `{"error": "<сообщение>"}`, если тело `POST` или `PUT` запроса не является корректным JSON-объектом.

#### Scenario: Битый JSON
- **WHEN** клиент отправляет `POST /api/tasks` с телом `{"title":`
- **THEN** система отвечает `400` с полем `error`

### Requirement: Просмотр списка задач
Система SHALL возвращать все задачи по запросу `GET /api/tasks` в виде JSON-массива, упорядоченного по времени создания (сначала старые).

#### Scenario: Пустой список
- **WHEN** задач нет и клиент отправляет `GET /api/tasks`
- **THEN** система отвечает `200` с телом `[]`

#### Scenario: Порядок задач
- **WHEN** клиент создал задачи «A», затем «B» и отправляет `GET /api/tasks`
- **THEN** система отвечает `200`, и «A» идёт в массиве раньше «B»

### Requirement: Изменение задачи
Система SHALL частично обновлять задачу по запросу `PUT /api/tasks/{id}`: менять только переданные поля `title` и/или `done`. Поля `id` и `createdAt` MUST NOT изменяться. Ответ `200` SHALL содержать обновлённую задачу.

#### Scenario: Отметить выполненной
- **WHEN** клиент отправляет `PUT /api/tasks/{id}` с телом `{"done": true}`
- **THEN** система отвечает `200`, у задачи `done = true`, а `title` не изменился

#### Scenario: Переименовать
- **WHEN** клиент отправляет `PUT /api/tasks/{id}` с телом `{"title": "Новое имя"}`
- **THEN** система отвечает `200`, у задачи `title = "Новое имя"`, а `done` не изменился

### Requirement: Удаление задачи
Система SHALL удалять задачу по запросу `DELETE /api/tasks/{id}` и отвечать `204` без тела. После удаления задача MUST NOT появляться в списке.

#### Scenario: Успешное удаление
- **WHEN** клиент отправляет `DELETE /api/tasks/{id}` существующей задачи
- **THEN** система отвечает `204`, и `GET /api/tasks` больше не содержит эту задачу

### Requirement: Несуществующая задача
Система MUST отвечать `404` с JSON-телом `{"error": "<сообщение>"}` на `PUT` и `DELETE` для `id`, которого нет, а также если `id` в пути не является целым числом.

#### Scenario: Изменение несуществующей задачи
- **WHEN** клиент отправляет `PUT /api/tasks/999` и задачи с таким `id` нет
- **THEN** система отвечает `404` с полем `error`

#### Scenario: Удаление несуществующей задачи
- **WHEN** клиент отправляет `DELETE /api/tasks/999` и задачи с таким `id` нет
- **THEN** система отвечает `404` с полем `error`

#### Scenario: Нечисловой идентификатор
- **WHEN** клиент отправляет `DELETE /api/tasks/abc`
- **THEN** система отвечает `404` с полем `error`

### Requirement: Неподдерживаемый метод
Система MUST отвечать `405` на HTTP-методы, не поддерживаемые для данного пути API.

#### Scenario: DELETE на коллекцию
- **WHEN** клиент отправляет `DELETE /api/tasks`
- **THEN** система отвечает `405`

### Requirement: Хранение только в памяти
Задачи SHALL храниться только в течение работы процесса. После перезапуска приложения список задач MUST быть пустым.

#### Scenario: Перезапуск
- **WHEN** клиент создал задачи и приложение перезапущено
- **THEN** `GET /api/tasks` возвращает `[]`
