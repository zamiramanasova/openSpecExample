# Design

## Context

Проект — пустой Maven-модуль на Java 17 (`org.example`, только `Main.java`), без зависимостей и без настроенного запуска. Мотивация — см. proposal.md, раздел Why; требования — `specs/task-management` и `specs/task-web-ui`.

## Goals / Non-Goals

**Goals:**
- Минимум кода и зависимостей: стандартная библиотека JDK плюс одна библиотека для JSON.
- Логика задач отделена от HTTP, чтобы следующие изменения (хранение в файле, фильтры) меняли одно место.
- Запуск одной командой из Maven и из IntelliJ (`Main.main`).

**Non-Goals:**
- Фреймворки (Spring, Javalin и т.п.), шаблонизаторы, сборщики фронтенда.
- Многопользовательская работа, аутентификация, HTTPS.
- Автотесты UI в браузере.

## Decisions

### HTTP-сервер: `com.sun.net.httpserver.HttpServer`
Входит в JDK, не требует зависимостей, достаточен для локального приложения. Порт 8080.
*Альтернативы*: Spring Boot — избыточен для цели (изучение OpenSpec); Javalin/Jetty — лишняя зависимость ради маршрутизации, которую легко сделать руками.

### JSON: Gson
Одна небольшая библиотека убирает ручной парсинг (экранирование, вложенность). `createdAt` хранится как `Instant` и сериализуется в строку ISO-8601 через зарегистрированный адаптер.
*Альтернативы*: ручной JSON — хрупко; Jackson — тяжелее, без выигрыша здесь.
Частичное обновление (`PUT`) разбирается как `JsonObject`, чтобы отличать «поле не передано» от `done: false`.

### Структура кода
```
org.example
  Main              -- создаёт хранилище, сервис, сервер; регистрирует обработчики
  Task              -- record (id, title, done, createdAt)
  TaskRepository    -- in-memory хранилище
  TaskService       -- бизнес-правила: trim, валидация title, частичное обновление
  TaskHandler       -- /api/tasks*: метод + путь -> вызов сервиса -> статус и JSON
  StaticHandler     -- отдаёт ресурсы из classpath:/static (index.html на "/")
  ValidationException / NotFoundException -- переводятся в 400 / 404 в TaskHandler
```
Сервис не знает об HTTP; обработчик не содержит правил валидации. Хранилище — отдельный класс, чтобы change «хранение в файле» заменял только его.

### Хранилище: `LinkedHashMap` под `synchronized` + `AtomicLong` для id
`HttpServer` по умолчанию обрабатывает запросы в одном потоке, но синхронизация дешева и снимает риск при смене executor. `LinkedHashMap` сохраняет порядок вставки = порядок создания.
*Альтернатива*: `ConcurrentHashMap` — не гарантирует порядок.

### Маршрутизация
Один контекст `/api/tasks`; путь разбирается вручную: `/api/tasks` (GET, POST) и `/api/tasks/{id}` (PUT, DELETE). Нечисловой `id` → 404, другой метод → 405. Все ответы API — `Content-Type: application/json; charset=utf-8`.

### Фронтенд: один `index.html` с встроенными CSS и JS
Ванильный JS, `fetch` к API; после каждого успешного изменения список перерисовывается по ответу сервера (без оптимистичных обновлений — так проще выполнить требование «не показывать несохранённое»). Переименование — по двойному клику на заголовке (поле ввода, Enter — сохранить, Esc — отмена). Ресурс лежит в `src/main/resources/static/` и читается из classpath, поэтому работает и из IDE, и из jar.

### Запуск
`exec-maven-plugin` с `mainClass = org.example.Main`: `mvn compile exec:java`. Из IntelliJ — обычный запуск `Main`.

## Risks / Trade-offs

- [`com.sun.net.httpserver` — пакет `jdk.httpserver`, не `java.*`] → Он официально поддерживаемый и экспортируемый модуль JDK; проект не модульный, ограничений нет.
- [Порт 8080 может быть занят] → Порт читается из переменной окружения `PORT`, по умолчанию 8080; при ошибке привязки — понятное сообщение в консоли.
- [Данные теряются при перезапуске] → Осознанно (см. spec «Хранение только в памяти»); решается следующим изменением.
- [XSS через `title` на странице] → Заголовки выводятся через `textContent`, не `innerHTML`.
- [Кодировка кириллицы] → UTF-8 явно при чтении тела запроса и записи ответа, `charset=utf-8` в заголовках.
